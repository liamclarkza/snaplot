# Expected dashboard behavior

> Historical comparison findings from before the API overhaul. Current authoring and framework contracts are documented in [ROW_API.md](ROW_API.md), [REACT_READINESS.md](REACT_READINESS.md) and the [root README](../../README.md). These observations are retained as evaluation evidence, not current API instructions.

This is a current-source audit of the chart lab and Snaplot core as of 17 September 2026. It checks the expectations that matter when a dashboard moves from a single chart to a grid of cards. The status column describes the present ownership boundary:

- **core supported** means the framework-free Snaplot API and implementation cover the behavior.
- **requires app glue** means the lab supplies it in `src/App.tsx` or an adapter; a chart library should not be credited with it.
- **missing** means the current default path has no complete behavior for the expectation.
- **intentional non-goal** means the repository explicitly excludes the capability from core.
- **not verified** means the source suggests a path, but this audit found no targeted fixture or browser check for the edge case.

The original subagent source audit did not perform a browser session, screenshot review, or new test run. The parent subsequently reproduced axis-title clipping, tick overlap and an invisible single point; see DEFAULTS_FINDINGS.md for that browser evidence. Existing claims in `EVALUATION.md` and `evidence/browser-audit.json` are cited as checked-in records, not repeated validation.

## Behavior matrix

| Dashboard expectation | Status | Current source evidence | Acceptance boundary |
| --- | --- | --- | --- |
| A card has an accessible legend, and toggling a run hides the same stable series in every matching chart. | **requires app glue** | The lab renders a labelled `role="group"` and `aria-pressed` buttons in `src/App.tsx:36-38`; `hidden` is shared across every renderer in `src/App.tsx:64,80,109`. Snaplot core exposes a renderer-independent `getLegendItems()` in `packages/snaplot/src/types.ts:1254-1259`, and the Solid legend toggles `visible` in `packages/snaplot/src/solid/SeriesLegend.tsx:40-67`. | The library already exports a DOM legend plugin as well as `getLegendItems()`. The lab chose custom React controls; do not infer that every consumer must hand-build a legend. Evaluate the default and optional React companion separately from cross-card state. |
| Missing observations create visible gaps and do not bridge across the missing run. | **core supported** | The lab converts `null` values to `NaN` in `src/adapters/SnaplotAdapter.tsx:7-10`; the gaps state preserves X and replaces Y values in `src/scenarios.ts:105-110`. Core documents `NaN` as a Y gap in `packages/snaplot/src/types.ts:9-14` and has regression coverage for segmented line/area paths in `packages/snaplot/src/renderers/LineRenderer.test.ts:57-78`. | Preserve the `NaN` convention in any record-to-column helper and keep `connectNulls`/equivalent behavior off unless an application opts in. |
| An empty result has a clear, useful empty state instead of a misleading chart. | **requires app glue** | `buildCharts()` returns zero rows for the empty state in `src/scenarios.ts:105-107`; the shell overlays “No observations in this window” in `src/App.tsx:39-46`. Core permits an empty columnar store (`packages/snaplot/src/core/Chart.ts:297-300`), but the chart API has no product copy or empty-state component. | The app currently owns loading, empty, no-results, and recovery copy. Evaluate a neutral library default plus an override slot instead of assuming all such glue is desirable. Keep the core render safe with zero-length data, and test that the overlay does not intercept an available chart interaction after recovery. |
| One-point and constant-value charts remain legible and do not collapse to a zero-size scale. | **missing** | Horizontal auto-ranging expands a single X value to `x - 1` / `x + 1` in `packages/snaplot/src/core/Chart.ts:1447-1449`. Vertical auto-ranging applies a zero padding to equal Y bounds in `packages/snaplot/src/core/Chart.ts:1581-1590`; `LinearScale.dataToPixel()` returns the pixel minimum when its domain is zero-width in `packages/snaplot/src/scales/LinearScale.ts:35-37,90-94`. The original dashboard fixtures omitted these cases; `src/audit/fixtures.ts` now provides explicit one-row and constant-Y cases. | Add explicit acceptance fixtures for one row, all-null Y, and constant Y. Define whether the default expands a constant Y domain or requires an explicit `yDomain`; do not rely on a screenshot-only judgment. |
| Numeric X, epoch-time X, and genuinely categorical labels have clear semantics. | **numeric/time: core supported; category: intentional non-goal** | `ScaleType` includes `linear`, `log`, and `time`, with time values defined as epoch milliseconds in `packages/snaplot/src/types.ts:20-25`; `TimeScale` generates local-calendar ticks in `packages/snaplot/src/scales/TimeScale.ts:54-107`. The repository explicitly excludes ordinal/equi-spaced X distributions in `README.md:88-90`. The lab’s airport and endpoint labels are numeric X values plus `xFormat` callbacks in `src/scenarios.ts:94-102`, not a category scale. | Treat date values as epoch numbers with an explicit time axis. Treat treatment/hour labels in this lab as application formatting over numeric positions. If true category spacing is required, open a separate API decision; do not call it a stale renderer bug. |
| Chart titles, subtitles, and axis titles stay attached to the card at narrow widths. | **requires app glue** | Card title/subtitle markup is in `src/App.tsx:33-35`; the chart adapter only passes the title as the React accessibility label in `src/adapters/SnaplotAdapter.tsx:40`. Core’s `ChartConfig` defines axes and series but no chart-title field in `packages/snaplot/src/types.ts:988-1018`; axis labels are part of `AxisConfig` in `packages/snaplot/src/types.ts:390-428`. | Keep card heading layout outside the renderer. A React recipe should require a sized parent and a separate heading; a chart’s axis labels should not be treated as a substitute for card title/subtitle. |
| Multiple charts can share cursor/highlight state, domains, or aligned gutters as one dashboard group. | **core sync keys supported; coordinated group helper is Solid-only** | The framework-free entry exports `ChartCore` and chart primitives in `packages/snaplot/src/core.ts:1-4`, while `createChartGroup` is exported from `packages/snaplot/src/solid.ts:6-18`. The group implementation provides sync keys, linked Y domains, gutters, and unlinking in `packages/snaplot/src/solid/createChartGroup.ts:75-103,150-187,225-243`. Core config already supports cursor/zoom/highlight sync keys independent of React or Solid. The comparison lab shares React visibility state but does not exercise those native channels; the missing convenience is the combined group lifecycle/domain/gutter helper. | Extract a framework-neutral group coordinator or add a React hook/provider. Acceptance must cover mount/unmount, reordered/subset series, independent chart lifetimes, cursor/highlight channels, optional zoom sync, domains, and both plot edges. |
| Hiding a series updates every renderer without changing the semantic series identity or data-column binding. | **requires app glue** | The shared `hidden` array is passed to each renderer in `src/App.tsx:107-109`; Snaplot retains all columns in series order while setting `visible` in `src/adapters/SnaplotAdapter.tsx:7-10,24-34`. Chart.js and Recharts apply their own hidden/filtered projections in `src/adapters/ChartjsChart.tsx:40-62` and `src/adapters/RechartsChart.tsx:138-145`; ECharts filters by stable IDs in `src/adapters/EchartsChart.tsx:102-105`. | Stable IDs and legend state belong to the application contract. Each adapter must preserve the same row values and update an existing instance where possible; visibility must not silently renumber an application’s series identity. |
| A threshold can target the intended Y axis when a chart has left and right scales. | **core supported; lab contract currently left-axis-only** | Core reference lines accept `axisKey` such as `y2` in `packages/snaplot/src/plugins/builtins/referenceLinesPlugin.ts:11-25,77-83`. Core supports extra axes and `yAxisKey` bindings in `packages/snaplot/src/types.ts:1011-1018,319-326`. The lab `ChartSpec.reference` has only a value/label (`experiments/chart-lab/src/types.ts:14-29`), and `SnaplotAdapter` always emits `{ axis: 'y' }` in `src/adapters/SnaplotAdapter.tsx:22,35-36`. | Add an axis key to the application contract before promising a right-axis threshold. Existing left-axis reference fixtures are valid; a secondary-axis reference needs a distinct fixture and browser check. |
| Scatter supports a useful X/Y cloud, missing points, and nearest-point details. | **core supported; lab arbitrary-X behavior not verified** | Core’s public series config supports independent `xDataIndex`/`yDataIndex`, encoded color/size, density, and extra tooltip fields in `packages/snaplot/src/types.ts:289-317`; the tooltip manager has a dedicated single-point path in `packages/snaplot/src/interaction/TooltipManager.ts:256-266`. The lab contract has one numeric `Row.x` and one value per series (`experiments/chart-lab/src/types.ts:6-12`), and its ML scatter fixture uses that shared X in `src/scenarios.ts:90`. The lab README explicitly defers arbitrary scatter X and linked cursors to a future round in `experiments/chart-lab/README.md:60-67`. | The current lab proves simple shared-X scatter only. For a native-capability round, add arbitrary X columns, missing X/Y points, dense clouds, nearest tooltip fields, selection identity, and a cross-chart keyed highlight acceptance test. |

## Backlog and stale-claim check

The repository’s current backlog already records theme integration, title spacing, and tick fitting as fixed work. The source retains semantic theme integration and axis-label measurement/thinning. Card headings belong to the application, whereas axis-title fitting belongs to the library. This distinction matters: the new defaults audit demonstrates actual core axis-title clipping even though the dashboard card headings wrapped successfully. Those earlier fixes must be distinguished from the newly reproduced edge cases in DEFAULTS_FINDINGS.md: long titles still clip and very long ticks still collide. Historical completion is not evidence that every content length fits.

The explicit category/equi-spaced-X exclusion in `README.md:88-90` is also current source policy, not a stale backlog item. The PUL-05 dual-axis/group concern mentioned in `EVALUATION.md:34-37` remains a validation and API-boundary topic: dual axes and axis-keyed references exist in core, while the lab contract does not exercise native sync keys or right-axis reference selection, and the combined group coordinator is still exported through Solid. It should be tracked as acceptance work rather than described as a reproduced rendering failure.

## Prioritized acceptance criteria

1. Add a small edge-fixture suite covering empty, all-null, one-row, constant-Y, mixed-sign, and valid log data. Define expected domains and visible states before comparing screenshots.
2. Keep the application-owned card shell contract explicit: fixed parent height, title/subtitle outside the renderer, accessible legend buttons, stable IDs, and an empty overlay owned by the app.
3. Decide the axis-selection shape for references (`y` versus `y2`) and add a dual-axis fixture where the left series is hidden while the threshold remains attached to the requested scale.
4. Specify the React grouping surface after the core/Solid behavior is extracted: lifecycle cleanup, cursor/highlight sync, optional zoom sync, keyed series mapping, domain coordination, and gutter alignment.
5. Run a separate scatter capability round for arbitrary X, nearest-point fields, dense data, and keyed selection. Keep true categorical X and large-scale streaming as explicit scope decisions.
