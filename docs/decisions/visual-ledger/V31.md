# V31: one domain policy — nice rounding is the padding, one-signed data never crosses zero

- **Commit:** `fix(axes)!: one domain policy without padding on nice bounds`
- **Milestone:** M10
- **Fixtures:** `marks/*`, `axes/*`, `layout/*`, `legend/*`, `theme/*`, `overlay/*` (every auto-ranged chart)
- **Before → after:**
  - Y (and scatter X) auto-ranges no longer add 5% padding on top of nice rounding: a bar maximum of 100 reads 0–100, a 40–44 series reads 40–44. The 5% pad remains for `nice: false`.
  - Data ≥ 0 never gets a negative axis and data ≤ 0 never a positive one (bars, areas, lines, scatter).
  - Area series include 0 in their domain (they fill to the baseline).
  - Numeric bar X axes span the first slot's left edge to the last slot's right edge (no phantom slots); the bar tick plan still places the ticks.
  - A second value axis defaults to the right; the first value axis the series use stays left.
- **Finding:** visuals-07, visuals-02:domain, visuals-08, render-10, render-22, backlog-10, backlog-13
- **Revert:** revert the commit with the subject above, then `npm run test:visual` and review the contact sheet.
